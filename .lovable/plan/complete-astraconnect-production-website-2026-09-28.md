# Complete AstraConnect Production Website

## Scope
- Preserve the existing AstraConnect visual system, product naming, routes, and interactive demos.
- Close the remaining gaps from the production brief rather than rebuilding working sections.

## Build plan
1. Complete global navigation with full product and solutions menus, compact-on-scroll behavior, mobile coverage, and clear independent-product messaging.
2. Expand the homepage into the complete narrative: dual product selector, Astra Voice four-stage story, conversation extraction, campaign simulator, CRM workflow, Astra Chat story, connected walkthrough, outcomes, and solutions preview.
3. Complete product experiences: Voice source switching and illustrative call flow; Chat pipeline movement plus compact Contacts, Deals, Broadcasts, Templates, Automation, and Analytics demonstrations.
4. Upgrade Astra Guide metadata, pause-to-explain behavior, contextual actions, accessible mobile/focus alternatives, and one-time extraction intervention.
5. Correct the required solution URL set, remove unverified integration/partnership claims, improve pricing/security truthfulness, and finish the conditional demo form with validation and an integration-ready submission boundary.
6. Restore strict animation ownership: Motion for interface feedback, GSAP/ScrollTrigger for section choreography, and Anime.js for isolated campaign/path/extraction sequences.
7. Add production SEO foundations including distinct route metadata, canonical URLs, sitemap, robots, structured data, and robust 404/error/loading presentation.
8. Verify all routes and core interactions at desktop, tablet, and mobile sizes; check reduced motion, keyboard access, overflow, console errors, types, and production output.

## Technical details
- Keep TanStack Start, React, TypeScript, Tailwind v4, shadcn/ui, Three.js, Motion, GSAP, Anime.js, Lucide, and Recharts; the project runtime does not support replacing TanStack Start with Next.js.
- Keep all demos local and explicitly labelled as illustrative/demo data. No backend or external message/call submission will be implied.
- Refactor only where needed into focused shared modules and keep existing semantic design tokens authoritative.
